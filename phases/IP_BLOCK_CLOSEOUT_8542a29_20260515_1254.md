## NEW-Pxx items surfaced during this block (full transparency)

Mid-block I surfaced this candidate item:

> `NEW-P10.X.repo-tenant-scoping-rollout-to-all-routes` — extend the CP9.33 SQL-layer tenant scoping kwarg to the receipts/evidence/narratives routes that use `get_receipt_by_id`.

**RETRACTED.** On inspection:

- The **receipts detail route** (`GET /v1/receipts/{receipt_id}`) deliberately loads the row first then returns **403** on cross-tenant — the route's docstring explicitly chose 403 over 404 because "we choose 403 because it's the truthful answer for an authenticated principal." Switching it to use the new SQL kwarg would change observable behaviour from 403 → 404, which contradicts a deliberate design decision.
- The **evidence-pack route** + **narratives route** check `tenant_id != principal.tenant_id` upfront before any SQL, so the SQL never sees a cross-tenant query in the first place. They call `list_receipts_with_snapshot_for_tenant(session, tenant_id, ...)` which is **already tenant-scoped by signature**. No gap exists.

The CP9.33 `tenant_id=` kwarg now exists as **defence-in-depth available for future routes** that want 404-not-403 semantics (the tabletop pattern), without forcing existing routes to change their behaviour.

So the phantom IP item is dropped. This RETRACTED disposition is recorded per Rule 3 (no silent drops).
